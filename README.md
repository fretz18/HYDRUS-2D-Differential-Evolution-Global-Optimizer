# Batch Global Optimizer for HYDRUS (DE + L-BFGS-B)

**Personal Project, use with caution**

An automated, stateful, and physics-guided global optimization framework for HYDRUS-2D solute transport. This script wraps the HYDRUS computational engine (`H2D_Calc64.exe`) to perform global inverse parameter estimation using a Hybrid Differential Evolution (DE) and local L-BFGS-B search algorithm.

It is specifically engineered to resolve the severe parameter identifiability and local minima issues (such as the "Zero-Concentration Flatline") encountered when fitting highly non-linear, kinetically limited solute breakthrough curves (BTCs) in novel composite materials (e.g., hydrogels, porous media with reactive surfaces).

## 1. Key Engineering Features

1. **Immunity to Code/GUI Collisions (Dynamic Header Parser)**
    
    HYDRUS input files (`Selector.in`) are formatted under strict, column-aligned Fortran rules. Toggling modules in the GUI shifts parameter columns, which crashes index-fixed parsing scripts. This optimizer uses a text-level token matching system. It identifies blocks by reading headers (e.g., locating `thr`, `ths`, and `n` on a line) and patches the exact corresponding indices, preventing character-width overflow and syntax corruption.
    
2. **Double-Read Validation Guardrail**
    
    To prevent silent parameter truncation (which occurs when written float representations exceed Fortran block widths), the script performs an immediate post-write read-back of `Selector.in`. If the written parameter differs from the intended float value by $> 0.01\%$, it aborts the step, logs the error to `patch_errors.log`, and penalizes the optimizer with a bad loss ($10^6$).
    
3. **Log-Space Scaling for Kinetic Search**
    
    Parameters such as mass transfer coefficients ($\alpha$) and sorption capacity ($K_s$) span multiple orders of magnitude ($10^{-5}$ to $10^{1}$). Standard linear search boundaries bias optimization towards high values. The script internally optimizes in $\log_{10}$-space and converts back to linear physical space during runtime execution.
    
4. **Stateful Session Execution**
    
    If a laptop or server crashes mid-batch, the script does not lose progress. On restart, it reads `optim_master_results.csv`, identifies completed runs, skips them, and appends new results to the same file without column corruption.
    
5. **Standard Error via Delta Method**
    
    Uncertainty is quantified by evaluating the local curvature of the loss surface. The script approximates the Hessian matrix at the global minimum using an `L-BFGS-B` local polishing step. Because some parameters are optimized in log-space, standard errors ($SE$) are mapped back to physical linear space using a first-order Taylor expansion (the Delta Method):
    
      
    
    $$SE(X_{linear}) \approx X_{linear} \cdot \ln(10) \cdot SE(X_{\log_{10}})$$


Your experimental breakthrough curve files must have a header matching exactly:

```

```

_Note: Time units must match `TUnit` in `Selector.in` (typically minutes), and concentration must be in relative units (_$C/C_0$_)._

## 3. Configuration Guide

All operations are controlled by adjusting variables in **Section 2 — Configuration** of the script.

### 3.1 Parameter States (`MODEL_CONFIGS`)

You must explicitly define which parameters the optimizer is allowed to float and which remain fixed.

```
MODEL_CONFIGS = {
    "params": [
        # active=True: Floating global parameter optimized in log space
        dict(name="Ks",    active=True, is_log=True, lo=0.01, hi=5.0),
        # active=False: Fixed value across all batch runs unless overridden by CSV
        dict(name="Beta",  active=False, fixed_value=1.00), 
        dict(name="Frac",  active=True,  is_log=False, lo=0.01, hi=0.50),
        dict(name="Alfa",  active=True,  is_log=True,  lo=1e-4, hi=1e-1),
        dict(name="SnkS1", active=True,  is_log=False, lo=0.0, hi=0.02),
    ]
}
```

### 3.2 Dynamic Batch Processing (`batch_runs.csv`)

If you are running different experiments, physical parameters (like Bulk Density or Porosity) change per column. You must define these in the `batch_runs.csv` file. For example

|   |   |   |   |   |   |
|---|---|---|---|---|---|
|**filename**|**Bulk.d**|**Ths**|**Hyd_Ks**|**DisperL**|**Beta**|
|observed0.csv|1.8|0.45|1|4|0.5|
|observed1.csv|1.40|0.33|0.6|1|0.7|

- **How Overrides Work:** If a header in `batch_runs.csv` matches an item in `VALID_PARAMS` _and_ that parameter is marked `active=False` in your script, the script intercepts it and dynamically patches it in `Selector.in` exclusively for that run.

- **Why this is critical:** It allows you to fit parameters like $K_s$ and $\alpha$ globally while locking hydraulic boundary constraints to their true measured values per column experiment.


## 4. Mathematical Mechanics of the Physics-Guided Loss Function

NOTE: This specific loss function was made for my low concentration, highly retarded Breakthrough curve. Make sure that the loss function you use is in accordance to your requirements.

To prevent the optimizer from getting trapped in the "Zero-Concentration Flatline" (where the optimizer chooses to simulate zero concentration to minimize root mean square errors on low-concentration peaks), the loss function utilizes a multi-objective hybrid formulation:

$$Loss = \text{Log-NRMSE} + (1 - KGE) + \text{Mass Penalty}$$

### 4.1 Log-Scale Normalized Root Mean Square Error (Log-NRMSE)

For low-concentration BTCs, standard RMSE treats small differences near zero as negligible. By transforming the signal to log-space, low-concentration arrival times are heavily weighted:

  

$$\text{Log-NRMSE} = \frac{\sqrt{\frac{1}{N} \sum \left[ \log_{10}(c_{obs} + \epsilon) - \log_{10}(c_{sim} + \epsilon) \right]^2}}{\mu_{\log_{10}(obs)}}$$

_Where_ $\epsilon = 10^{-5}$ _is a numerical stabilizer, and simulated concentrations are clipped at_ $0$ _using_ $\max(C_{sim}, 0)$ _to prevent negative value `NaN` runtime oscillations._

### 4.2 Kling-Gupta Efficiency (KGE)

KGE ensures the shape, peak timing, and dispersion of the plume are structurally correct by assessing correlation, bias, and variability independently:

  

$$KGE = 1 - \sqrt{(r - 1)^2 + (\beta_{bias} - 1)^2 + (\gamma_{var} - 1)^2}$$

- $r$ **(Pearson Correlation):** Matches phase alignment and arrival timing.
    
- $\beta_{bias} = \mu_{sim}/\mu_{obs}$**:** Constrains average mass matching.
    
- $\gamma_{var} = \frac{\sigma_{sim}/\mu_{sim}}{\sigma_{obs}/\mu_{obs}}$**:** Constrains the peak height and curvature.
    

### 4.3 Weak-Form Mass Balance Penalty

The script reads `tPulse` directly from Block D of `Selector.in` and uses Trapezoidal integration to compute simulated recovery area ($M_{sim}$) versus observed recovery area ($M_{obs}$). If the simulated recovery falls below 70% of the observed recovery, a massive penalty term is triggered:

  

$$\text{Mass Penalty} = 2.0 \cdot \frac{M_{obs}}{M_{sim} + \epsilon}$$

_This constraint forces the optimizer to preserve mass transport, completely eliminating flat-line strategies._

## 5. Running the Optimizer

1. Open your model project in the HYDRUS GUI. Click **Save**, then close the GUI (this establishes a clean `Selector.in` baseline).
    
2. Configure your parameters in the Python script (`MODEL_CONFIGS` and `PROJECT_DIR`).
    
3. Set up your run instructions in `batch_runs.csv`.
    
4. Open a command prompt and execute:
    
    ```
    python hydrus_global_optimizer.py
    ```
    

### 5.1 Console Outputs to Watch

During execution, a continuous terminal ticker monitors real-time performance:

```
  [0283] NEW BEST LOSS: 1.32896 (MassErr: 2.991) | Ks=0.3331  Frac=0.6378  Alfa=0.2275  SnkS1=0.01641
```

- **MassErr:** Shows the integration difference of the area under the curve.
    
- **BEST LOSS:** Decreases as Differential Evolution converges.
